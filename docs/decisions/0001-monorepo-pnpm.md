# ADR 0001: مستودع واحد (Monorepo) بإدارة pnpm

- **الحالة:** منفّذ
- **التاريخ:** 2026-11-13
- **نُفّذ في:** commit `21b0ecd`، وأُضيف أمر التشغيل الموحّد في `6c4ad72`

## السياق

المشروع يتكون من خادم وواجهة، ويحتاجان مشاركة أشكال البيانات (مثل شكل رد `/api/health`). صاحبة المشروع تعمل وحدها، فيجب أن يبقى التشغيل والصيانة بسيطين.

## القرار

- مستودع Git واحد يضم ثلاثة أجزاء: `apps/api` و`apps/web` و`packages/shared`.
- الأجزاء معرّفة في `pnpm-workspace.yaml`، وأسماؤها `@alaa/api` و`@alaa/web` و`@alaa/shared`.
- pnpm 10 أو أحدث، وNode 22 أو أحدث، مع `engine-strict=true` في `.npmrc`.
- إعدادات TypeScript الصارمة المشتركة في `tsconfig.base.json`، ويرثها كل جزء.
- أوامر الجذر تشغّل الأجزاء معاً، مثل `pnpm dev` و`pnpm check`.

## البدائل التي لم تُختر

- **مستودعان منفصلان للخادم والواجهة:** يجعل أي تغيير مشترك يحتاج commitين منفصلين، ويصعّب مشاركة الأنواع.
- **npm workspaces:** يعمل أيضاً، لكن pnpm أسرع ويوفر مساحة القرص.

## النتائج

- تغيير يمس الخادم والواجهة معاً يُحفظ في commit واحد.
- **ملاحظة:** `packages/shared` لا يحتوي كوداً بعد، وفيه `package.json` فقط. نوع `HealthResponse` مكرر حالياً في الخادم والواجهة، ونقله إلى الحزمة المشتركة مخطط لاحقاً.

## متى نراجعه

إذا احتاج المشروع أداة بناء للمستودعات الكبيرة (مثل Turborepo) بسبب بطء الأوامر مع زيادة حجم الكود.
