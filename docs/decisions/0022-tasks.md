# ADR 0022: المهام

- **الحالة:** منفّذ (الخطوات 8.1 إلى 8.3).
- **التاريخ:** 2026-11-16
- **وافقت عليه:** صاحبة المشروع، بعد مراجعة SQL ونتائج 53 فحصاً على قاعدة بيانات حقيقية.

## قرارات صاحبة المشروع

- المهام للإدارة، ويمكن تعليم مهمة **«ظاهرة للعميل»** فيراها في بوابته للقراءة فقط.
- المهمة عامة، أو لعميل، أو لحملة من حملات نفس العميل.
- العرض: قائمة بفلاتر، ولوحة أعمدة (للتنفيذ / قيد العمل / منجزة).
- أولوية وتاريخ استحقاق، وتعليقات، ومهام متكررة، ومهام تلقائية من النظام.

## القرار

**1. ما تفرضه قاعدة البيانات** (migration `20261116120000_create_tasks`)

- حملة المهمة يجب أن تتبع عميلها (trigger)، والمهمة المشتركة يجب أن يكون لها عميل.
- لكل مصدر حقوله: يدوية (منشئها مطلوب)، متكررة (قاعدة ويوم، مرة واحدة لكل يوم)، تلقائية (مفتاح فريد، مرة واحدة لكل سبب).
- وقت الإنجاز تضعه قاعدة البيانات عند «منجزة» وتمسحه عند إعادة الفتح. أصل المهمة ومنشئها لا يتغيران.
- لا حذف: المهمة تُلغى، والقاعدة تُوقف أو تنتهي، والتعليق لا يُعدّل ولا يُحذف.

**2. التعليقات داخلية دائماً**: لا يرسلها الـ API للعميل، ولا يُنسخ نصها إلى سجل التدقيق (رقمها وطولها فقط).

**3. المهام المتكررة والتلقائية**: لا توجد جدولة في الخلفية بعد، فتُنشأ عند فتح صفحة المهام أو اللوحة الرئيسية، وكل إنشاء idempotent (لا تكرار).

- المتكررة: لا تُنشأ لأيام قبل وجود القاعدة، وتُعوَّض الأيام الفائتة حتى 31 يوماً.
- التلقائية: مسودة فاتورة تنتظر المراجعة، وفاتورة متأخرة، وحملة نشطة بلا أرقام 3 أيام أو أكثر. وتُغلق وحدها («منجزة») عندما يزول السبب.

**4. الاختبارات**: كل اختبار للمهام يعمل داخل transaction تُلغى في نهايته (`testing/rollback-db.ts`)، لأن المهام والتعليقات لا تُحذف ولا يجوز أن تبقى في قاعدة الاختبار.
